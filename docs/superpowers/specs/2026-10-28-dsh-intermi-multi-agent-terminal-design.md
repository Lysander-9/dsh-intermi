# dsh-intermi: 本机多 Agent 终端工作台

日期：2026-10-28
状态：待用户评审

## 意图

面向个人开发者，在 DSH NEXT 右侧边栏集中查看并切换多个 Agent 正在使用的真实持久 Shell。用户能够迅速识别会话、进入对应终端继续操作；切换和关闭面板不应创建替代 Shell，也不应丢失原 PTY 的运行状态。

## 目标

- 一个 Agent 可拥有一个或多个持久 PTY；列表清楚显示 Agent 与终端名称、工作目录和活动状态。
- 使用单一的大型终端视图，通过紧凑列表选择 Agent/Shell；选择后连接既有 PTY。
- 切换终端或关闭再打开边栏后，Shell 继续运行，终端恢复可用的滚动历史和连接状态。
- 用户键盘输入与 Agent 工具调用进入同一个 PTY，支持交互式进程和持续会话。
- 多会话切换响应迅速；当前选择有明确标记，掉线、结束和重连状态可见。
- 本机优先：会话记录和偏好存放在 DSH 用户目录，不要求云账号或团队服务。

## 非目标（首版）

- 团队共享、云端运行、成员权限管理和组织级审计策略。
- 多终端平铺/网格、命令全文搜索、审计报表和远程控制链接。
- 创建与 Agent 分离的用户 Shell；终端仍由 DSH Agent 对应的 PTY 所有。
- 用一份日志替代真实终端。终端画面应由 PTY 字节流驱动，日志用于恢复、检索等辅助用途。

## 用户流程

1. 打开 dsh-intermi 后，在窄会话栏看到可用 Agent 及其 Shell 名称和状态。
2. 选择一个 Shell，右侧主区域连接该会话的现有 PTY，恢复近期屏幕状态并接收实时输出。
3. 用户直接在终端输入；Agent 后续操作继续使用相同的 sessionId 和 PTY。
4. 选择另一个 Agent 时，解除前一个视图连接并连接目标 PTY；前一个 PTY 保持运行。
5. 重新打开插件时读取 DSH 当前存活的 PTY 清单，并恢复上次选择；已结束会话明确标记为不可交互。

## 方案与选择

1. **列表 + 单终端视图（选择）**：终端保持最大空间，切换时建立到目标 PTY 的连接。复杂度和资源占用可控，符合用户已确认的首版体验。
2. **多终端平铺**：适合同时盯多个任务，但会压缩每个终端的空间并增加渲染、尺寸管理与输入焦点复杂度，暂缓。
3. **仅命令活动面板**：适合回顾操作，但无法满足用户接管实时 Shell 的首要需求，不作为产品主入口。

## 当前实现与约束

当前插件从 DSH `agents` 与 `terminals` 服务读取 Agent 所拥有的 PTY，使用 xterm.js 通过 WebSocket 转发输入、输出和尺寸变化。Host 还维护内存终端历史（目前每 PTY 上限 512 KiB），并把工具事件追加到 `%USERPROFILE%\\.dsh\\itatmn\\events.jsonl`。该结构支持首版方向，但持久输出恢复、插件重载后的状态重建、Agent/PTy 生命周期同步和高频多会话切换仍需验证与加固。

实现时必须继续使用 DSH 注册的原始 Agent 所有权和真实 sessionId；视图断开不得关闭 PTY。WebSocket 连接应按需建立，切换时清理旧监听器和尺寸观察器，避免多个会话同时向同一屏幕写入。会话快照与历史记录要有版本、边界和错误恢复策略。

## 验收标准

- 两个或更多 Agent 各自打开 PTY 后，都能在同一面板的会话列表中识别并切换。
- 在终端 A 运行持续进程，切到 B 再切回 A，A 的进程和 cwd 仍在，输出没有交叉。
- 用户在 A 中输入的命令能由 A 当前 PTY 执行，Agent 继续复用 A 的 sessionId。
- 关闭并重新打开插件面板后，仍可发现所有存活 PTY；选择恢复后显示对应历史并继续实时交互。
- 删除或关闭一个 PTY 后，该项状态及时更新；其它 Agent 的终端不受影响。
- 连接失败、PTY 已结束、历史不可恢复等情况有清晰状态提示，且不会伪装为成功连接。

## 后续方向

核心体验稳定后，再增加命令时间线与搜索、筛选、导出和可选审计留存；最后评估团队共享需求。审计数据应区分 Agent 工具发起的命令与用户直接键入的输入来源。
